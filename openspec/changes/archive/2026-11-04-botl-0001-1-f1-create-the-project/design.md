# Design

## Context

The repository holds only README, LICENSE and OpenSpec scaffolding (see proposal.md — Why). The local machine provides Maven 3.9 running on a newer JDK (24/25) and no JDK 21 installation.

## Goals / Non-Goals

**Goals:**
- A root-level Maven project generated by the Quickstart archetype, compiling at Java 21 level, with an executable JAR.

**Non-Goals:**
- Any domain model, command protocol, or extra infrastructure (logging frameworks, CI, wrappers).

## Decisions

- **Generate with the archetype, then move to the repository root.** Run `mvn archetype:generate -DarchetypeGroupId=org.apache.maven.archetypes -DarchetypeArtifactId=maven-archetype-quickstart -DarchetypeVersion=1.5` non-interactively with `groupId=es.upm.park`, `artifactId=amusement-park`, `package=es.upm.park`, in a temporary directory and move `pom.xml` and `src/` to the root. Alternative (hand-written POM) rejected: the request requires archetype generation. Root placement keeps later tooling (`mvn test` from root, SDDX analysis) simple.
- **Java level via `maven.compiler.release=21`.** `release` (rather than source/target) makes javac enforce the Java 21 API as well as language level, so building on a newer JDK still guarantees JDK 21 compatibility. Assumption recorded: no JDK 21 is installed locally; verification uses `release=21` on the available JDK.
- **Executable JAR via `maven-jar-plugin` manifest `mainClass`.** The archetype has no dependencies at runtime, so a plain JAR with `Main-Class` suffices; a shaded/fat JAR plugin is unnecessary and rejected as nonessential infrastructure.
- **Keep the archetype's JUnit 5 test (`AppTest`)** as the basic test structure.

## Risks / Trade-offs

- [Built on a JDK newer than 21] → `release=21` restricts the API to Java 21; the produced bytecode (major version 65) runs on JDK 21.
- [Archetype 1.5 pins plugin versions that may age] → acceptable; versions are explicit and reproducible.
