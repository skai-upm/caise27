# Spec Delta

## MODIFIED Requirements

### Requirement: Delete user
`USER DELETE;Correo;Contraseña` SHALL delete the user identified by the email only if the user exists, the supplied password matches the stored one, and the user has no ticket (individual or generated by a group ticket) dated on or after the current date. On deletion the user SHALL be removed from every group and the persistent files SHALL be updated. Otherwise the user SHALL NOT be deleted and an error SHALL be reported.

#### Scenario: Successful deletion
- **WHEN** user `ana@correo.com` with password `Clave1!` exists and `USER DELETE;ana@correo.com;Clave1!` is executed
- **THEN** the user is removed and no longer appears in the persistent file

#### Scenario: Wrong password
- **WHEN** `USER DELETE;ana@correo.com;Wrong1!` is executed
- **THEN** the user is not deleted and an error is reported

#### Scenario: Unknown email
- **WHEN** `USER DELETE;nadie@correo.com;Clave1!` is executed
- **THEN** nothing is deleted and an error is reported

#### Scenario: Current or future ticket blocks deletion
- **WHEN** the date is 2026-10-01, Ana has ticket T001 for 2026-10-15 and `USER DELETE;ana@correo.com;Clave1!` is executed
- **THEN** deletion is rejected

#### Scenario: Past ticket does not block deletion
- **WHEN** `SYSTEM DATE;2026-10-16` is then executed and the deletion is retried
- **THEN** Ana is deleted and T001 is kept as a historical record

#### Scenario: Deleted user leaves groups
- **WHEN** a user who belongs to G01 is deleted
- **THEN** G01 no longer lists that user
