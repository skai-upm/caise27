# Design

## Context

Layers: `presentation` (`CommandProcessor`), `business.controller` (`ParkController`), `business.service` (managers), `business.model`, `persistence`. `TicketManager` holds the individual tickets bought with `TICKET CREATE` (`getTickets()`) and the group tickets (`getGroupTickets()`), whose constituent `IndividualTicket`s live only inside each `GroupTicket`. So "direct" and "constituent" tickets are already structurally separate. Prices are captured per ticket (`IndividualTicket.getPrice()`, `GroupTicket.getPrice()` = discounted total).

## Goals / Non-Goals

**Goals:**
- A textbook Builder (builder abstraction, concrete builders, director, product) whose steps decide which sections exist.
- Charges taken from the stored ticket prices, never recomputed.

**Non-Goals:**
- Passes and their invoice lines (introduced in a later change, see Deferred requirements).
- Persisting invoices.

## Decisions

- **Package `business.invoice`.**
  - **Product:** `Invoice` (`title`, `sections`, `total`), `InvoiceSection` (`title`, `lines`), `InvoiceLine` (`description`, `amount`). These are immutable, and their lists are unmodifiable copies.
  - **Builder abstraction:** `abstract class InvoiceBuilder` with the steps `buildHeader()`, `buildTicketSection()`, `buildTotal()` and the result `getResult()`. It holds the in-progress `title`, `sections` and `total`, and offers a protected `addSection(title, lines)` helper that **ignores empty line lists**, which implements the omission rule in one place. `buildTotal()` is implemented in the abstraction as the sum of all section lines, because both variants total the same way.
  - **Concrete builders:**
    - `UserInvoiceBuilder(User, List<IndividualTicket> directTickets)`: header `Invoice for user <name> <surname> <email> (DNI <dni>)`, section `Individual tickets` with one line per ticket `<id> <date>` priced at `ticket.getPrice()`.
    - `GroupInvoiceBuilder(Group, List<GroupTicket>)`: header `Invoice for group <id> (<name>)`, section `Group tickets` with lines `<id> <date> (<n> members, <d>% discount)` priced at `groupTicket.getPrice()`.
  - **Director:** `InvoiceDirector.construct(InvoiceBuilder)` calls header → ticket section → total and returns the result. A later change adds its pass step here and in the builder abstraction.
  - Using an abstract class instead of an interface lets the shared state and the omission helper live once. The source asks for "a Builder abstraction", which either form satisfies.
- **Selecting the data.**
  - User invoices use `tickets.getTickets()` filtered by `belongsTo(user)`, which are only the tickets bought with `TICKET CREATE`. Constituent tickets are never in that collection, so they cannot be double counted.
  - Group invoices use `tickets.getGroupTickets()` filtered by `belongsTo(group)`.
  - Past tickets are included, because an invoice reflects all purchases still recorded.
- **Controller.** `ParkController.createUserInvoice(email)` looks the user up through `UserManager.findByEmail` (error `No user with email ...`). `createGroupInvoice(id)` uses `requireGroup`. Both choose the builder and run the director.
- **Presentation.** `CommandProcessor` parses `INVOICE CREATE;<type>;<id>` (2 parameters, type case-insensitive) and formats:
  ```
  OK: Invoice for user Ana Garcia Lopez <ana@correo.com> (DNI 12345678Z)
    Individual tickets:
      T001 2026-10-15: 40.00
    TOTAL: 40.00
  ```
  Amounts use two decimals with `.`.
- **UML.** Add the invoice classes. `InvoiceBuilder` is abstract, with `UserInvoiceBuilder` and `GroupInvoiceBuilder` inheriting from it. Compositions `Invoice *--> InvoiceSection : sections`, `InvoiceSection *--> InvoiceLine : lines` and `InvoiceBuilder *--> InvoiceSection : sections`. Associations from the builders to `User`/`Group` and to the ticket lists. Usage arrows from `ParkController` to the director and concrete builders, since they are created locally.

## Deferred requirements (passes)

When personal passes exist (Delivery 3, SpeedPass/Special Pass change), invoices SHALL also include:
- in a user invoice, a personal-passes section listing the passes the user bought, including passes attached to tickets generated by a group ticket
- in a group invoice, no member passes

That change will add a `buildPassSection()` step to `InvoiceBuilder` and the director. It is recorded here and not implemented now, because passes do not exist yet.

## Risks / Trade-offs

- [Abstract builder holds state] → each invoice uses a fresh builder instance created by the controller.
