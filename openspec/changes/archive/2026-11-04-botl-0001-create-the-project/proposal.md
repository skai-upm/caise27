# Proposal

## Why

The repository contains only OpenSpec scaffolding and no application code. Before any amusement-park functionality can be built, the project needs a reproducible Java 21 Maven skeleton, generated from the standard Quickstart archetype, with a working test setup and an executable JAR, so that every later change starts from a known-good build.

## What Changes

- Generate a Maven project from `org.apache.maven.archetypes:maven-archetype-quickstart` at the repository root.
- Pin compilation to Java 21 (`maven.compiler.release=21`).
- Keep the standard Quickstart layout: `pom.xml`, `src/main/java/...` with the generated entry-point class `App`, and `src/test/java/...` with the generated basic test `AppTest`.
- Configure `maven-jar-plugin` so `mvn package` produces a JAR whose manifest declares the main class, making it runnable with `java -jar`.
- Verify `mvn test` and `mvn package` succeed on JDK 21.
- No amusement-park domain functionality (users, commands, tickets, groups, attractions) is added.

## Capabilities

### New Capabilities
- `application-bootstrap`: Maven/JDK 21 build toolchain, standard Quickstart project structure, executable entry point, executable JAR packaging and basic test infrastructure.

### Modified Capabilities
_None._

## Impact

- New files: `pom.xml`, `src/main/java/es/upm/park/App.java`, `src/test/java/es/upm/park/AppTest.java`.
- Build output under `target/` (already gitignored).
- No dependencies beyond those generated by the archetype (JUnit for tests).
- Assumption: Maven coordinates `es.upm.park:amusement-park` and base package `es.upm.park` are chosen because the source does not name them.
