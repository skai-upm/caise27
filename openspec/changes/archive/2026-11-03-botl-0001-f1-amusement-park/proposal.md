# Proposal

## Why

The Amusement Park assignment needs a verifiable command-line foundation before any park-specific features can be built: a standard Java 21 / Maven project that packages into an IDE-independent executable JAR, and persistent user management driven by text commands that behave identically whether typed interactively or read from a command file. This change delivers that complete first delivery (milestones F0-C01, F0-C02 and F1-C01…F1-C09 of the source, archived verbatim in `.botl/proposals/…/1.F1_Amusement_Park_Improved_OpenSpec.md`, Appendix A) as one consolidated change.

## What Changes

- Create a Java 21 Maven project from the Apache Maven Quickstart archetype with the standard directory layout (the repository currently contains no Java code).
- Configure `mvn package` to produce an executable JAR that starts with `java -jar` in interactive mode (no arguments) or file mode (first argument is a command file path).
- Introduce an encapsulated user with first name, surnames, DNI, email, password, telephone and card number; the DNI is immutable after creation.
- Add user-data validation (Spanish DNI check letter, `text@text.xxx` email with three-character extension, password with upper/lower/digit/symbol, 16-digit card) using only basic String operations and `split` — no regular expressions or external libraries.
- Add the `USER CREATE;FirstName;Surnames;DNI;Email;Password;Phone;Card` command with DNI and email uniqueness checks performed before any state change.
- Persist users between runs in a semicolon-separated text file, one user per line, via a persistence component separate from the user model and the main class.
- Add `USER DELETE;Email;Password` (credential check before removal) and `USER UPDATE;Email;Password;Field;NewValue` (enum-defined fields NAME, SURNAME, EMAIL, PASSWORD, PHONE, CARD; DNI not modifiable; same validation and uniqueness rules as creation).
- Process commands from standard input or from a file through one shared parser/executor, in order, ignoring blank file lines, handling a missing/unreadable file in a controlled way.
- Add `HELP` (lists command syntax) and `EXIT` (controlled termination; no later file lines are processed).
- Ensure invalid or malformed commands never terminate the application unexpectedly and never leave partial state.

## Capabilities

### New Capabilities
- `project-initialization`: Java 21 Maven Quickstart project structure that compiles and tests with Maven.
- `executable-application`: Standalone executable JAR with a defined entry point, interactive and file start modes.
- `user-domain-model`: User entity with the seven required attributes, encapsulated state and immutable DNI.
- `user-data-validation`: Validation rules for DNI, email, password and card number without regular expressions or external libraries.
- `user-creation`: `USER CREATE` command creating unique, valid users.
- `user-persistence`: Text-file persistence of users between runs, isolated from the user model and main class.
- `user-deletion`: `USER DELETE` command removing a user only after email/password verification.
- `user-updates`: `USER UPDATE` command modifying enum-defined fields under creation-time validation and uniqueness rules.
- `command-file-execution`: Shared command processing for interactive and file input, ordering and blank-line handling, controlled file errors.
- `help-and-exit`: `HELP` command syntax listing and `EXIT` controlled termination in both modes.
- `delivery-one-integration`: Delivery-wide technical restrictions (Java standard library only, no databases/frameworks/regex/encryption) and robust end-to-end behavior.

## Impact

- New files: `pom.xml`, `src/main/java/**`, `src/test/java/**` (Maven standard layout); `.gitignore` already ignores `target/`.
- Runtime data: a user data file (default `users.txt` in the working directory) is created/updated at runtime.
- Dependencies: Java standard library only at runtime; JUnit 5 as a test-scoped dependency (as generated by the Quickstart archetype).
- Build: `mvn package` must produce `target/amusement-park.jar` runnable with `java -jar` (see design.md for the `nombre-aplicacion` placeholder decision).
- Git: the source prescribes eleven milestone commit messages; how these interact with the batch harness is recorded in design.md.
