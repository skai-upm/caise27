# Design

## Context

The repository currently contains only OpenSpec scaffolding and a `.gitignore` with Maven entries; there is no source code. See proposal.md for motivation.

## Goals / Non-Goals

**Goals:**
- A quickstart-archetype project that builds on Java 21 and packages an executable JAR.

**Non-Goals:**
- Any domain model, command processing, or persistence.
- Shaded/fat JARs (no runtime dependencies exist yet).

## Decisions

- **Generate with the archetype, in place.** Run `mvn archetype:generate` (non-interactive) with `groupId=es.upm.parque`, `artifactId=parque`, `package=es.upm.parque`, then move the generated files to the repository root so the repository *is* the Maven project. Alternative (hand-writing the files) rejected because the requirement is that the project be generated by the archetype.
- **Java 21 via `maven.compiler.release=21`.** `release` (rather than `source`/`target`) also restricts the API to Java 21, so building with a newer JDK still produces a Java 21-compatible artifact.
- **Executable JAR via `maven-jar-plugin` manifest.** Set `archive.manifest.mainClass` to `es.upm.parque.App` and `finalName` to `parque` so the artifact is `target/parque.jar`, matching the run commands used by later deliveries (`java -jar target/parque.jar`). An assembly/shade plugin is unnecessary while there are no runtime dependencies.
- **Keep archetype test framework** (JUnit as generated) and the generated `AppTest`.

## Risks / Trade-offs

- [The build machine may not have JDK 21 exactly] → `release=21` lets any JDK ≥ 21 compile Java 21 bytecode and API.
- [Archetype version changes default plugin versions] → Pin the archetype version on generation and keep the generated plugin management section.
