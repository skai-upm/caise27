# Proposal

## Why

The amusement-park project has no code yet. Delivery 1 (F1) needs an independently runnable Java 21 / Maven application that offers persistent user management through a text-command interface usable from the terminal or from a command file. This is the foundation that later deliveries (attractions, groups, tickets, passes) will build on, so it must be delivered without anticipating those features.

## What Changes

Delivered as three incremental stages inside this single change, each keeping the project buildable and tested and preserving the previous stage's behavior:

1. **Bootstrap** – Generate a Maven Quickstart (`org.apache.maven.archetypes:maven-archetype-quickstart`) project on JDK 21 with an executable main class, executable JAR packaging and the basic JUnit test structure. No domain functionality.
2. **User management** – Encapsulated `User` model (immutable DNI), validation of DNI (Spanish checksum), email (`texto@texto.xxx`, 3-char extension, no regex), password (upper/lower/digit/symbol, no regex), card (exactly 16 digits); DNI/email uniqueness; `USER CREATE`, `USER DELETE`, `USER UPDATE` commands parsed with `String.split`; an enum of updatable fields; a dedicated persistence class storing users in a semicolon-separated text file and reloading them at startup.
3. **Execution and control** – One shared command processor fed either by standard input (no arguments) or by a file given as the first argument; `HELP` and `EXIT`; blank lines ignored; invalid commands, insufficient parameters and unreadable files handled without uncontrolled termination.

Out of scope: attractions, groups, tickets, fast passes, encryption, databases, frameworks, third-party libraries, regular expressions, and design patterns introduced only for later deliveries.

## Capabilities

### New Capabilities
- `project-build`: Java 21 / Maven Quickstart project structure, test execution with `mvn test`, and executable JAR packaging.
- `user-management`: User data model, input validation rules, uniqueness constraints, and the `USER CREATE` / `USER DELETE` / `USER UPDATE` operations.
- `user-persistence`: Storage of users in a semicolon-separated text file by a dedicated class, and reconstruction of users at startup.
- `command-execution`: Text-command parsing, interactive and file input modes sharing one processor, `HELP`, `EXIT`, and controlled error handling.

## Impact

- New Maven project at the repository root (`pom.xml`, `src/main/java`, `src/test/java`).
- New runtime data file (`users.txt` by default) created in the working directory at runtime; it is a data artifact, not source.
- Test dependency: JUnit (as generated by the Quickstart archetype). No runtime third-party dependencies.
