# application-bootstrap Specification

## Purpose

Defines the build, structure, entry point, packaging and test infrastructure that every later amusement-park feature builds on.

## Requirements

### Requirement: Java 21 Maven build
The project SHALL be built with Maven and SHALL compile its sources targeting the Java 21 language level and platform API.

#### Scenario: Fresh test build succeeds
- **GIVEN** a fresh checkout with a JDK supporting release 21 and Maven available
- **WHEN** `mvn test` is run from the repository root
- **THEN** the sources compile and all tests pass with a successful build

#### Scenario: Java 21 target is declared
- **GIVEN** the project build file
- **WHEN** it is inspected
- **THEN** the compiler release level is 21

### Requirement: Standard Quickstart layout
The project SHALL keep the directory structure generated by `org.apache.maven.archetypes:maven-archetype-quickstart`: a root `pom.xml`, production code under `src/main/java` and tests under `src/test/java`.

#### Scenario: Layout review
- **GIVEN** the repository
- **WHEN** its structure is reviewed
- **THEN** `pom.xml`, `src/main/java/<package>/App.java` and `src/test/java/<package>/AppTest.java` are present

### Requirement: Executable JAR packaging
Packaging the project SHALL produce a JAR whose manifest declares the application entry-point class, so that it can be started with `java -jar`.

#### Scenario: Packaged JAR starts
- **GIVEN** a successful `mvn package`
- **WHEN** the produced JAR is run with `java -jar`
- **THEN** the application starts and exits normally without a "no main manifest attribute" error

### Requirement: Basic test infrastructure
The project SHALL include a unit-testing setup executed by the Maven `test` phase, with at least one test.

#### Scenario: Tests are executed
- **GIVEN** the project
- **WHEN** `mvn test` runs
- **THEN** at least one test is executed and reported as passed

### Requirement: No domain functionality
At this stage the production code SHALL NOT contain amusement-park business functionality (users, commands, tickets, groups, attractions).

#### Scenario: Production code review
- **GIVEN** the completed change
- **WHEN** `src/main/java` is reviewed
- **THEN** it contains only the archetype entry point and no domain classes
