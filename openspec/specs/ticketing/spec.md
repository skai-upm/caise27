# ticketing Specification

## Purpose

Lets registered users buy individual tickets for a date, keeps them as persistent history, and defines how tickets restrict deletions.

## Requirements

### Requirement: Buy individual ticket
The system SHALL accept `TICKET CREATE;<id>;<correo>;yyyy-MM-dd` and create a ticket with that identifier, date of use, a reference to the existing user and the current individual price, reporting `OK TICKET CREATED -> <precio>` with two decimals. Ticket identifiers SHALL be unique among all tickets. Unknown users, invalid dates and dates before the system date SHALL be rejected.

#### Scenario: Buy ticket
- **WHEN** Ana exists, the price is 40.00, the system date is 2026-10-01 and `TICKET CREATE;T001;ana@correo.com;2026-10-15` is processed
- **THEN** the system reports `OK TICKET CREATED -> 40.00` and T001 belongs to Ana for 2026-10-15

#### Scenario: Unknown user
- **WHEN** `TICKET CREATE;T002;nadie@correo.com;2026-10-15` is processed
- **THEN** the system reports an error and no ticket is created

#### Scenario: Duplicate identifier
- **WHEN** T001 exists and `TICKET CREATE;T001;ana@correo.com;2026-10-20` is processed
- **THEN** the system reports an error

#### Scenario: Date in the past
- **WHEN** the system date is 2026-10-01 and `TICKET CREATE;T003;ana@correo.com;2026-09-30` is processed
- **THEN** the system reports an error and no ticket is created

### Requirement: Delete individual ticket
The system SHALL accept `TICKET DELETE;<id>` and delete the ticket only when its date is strictly later than the system date. Tickets that belong to a group ticket SHALL NOT be deleted with this command.

#### Scenario: Future ticket
- **WHEN** the system date is 2026-10-01 and `TICKET DELETE;T001` is processed for a ticket dated 2026-10-15
- **THEN** the system reports `OK TICKET DELETED` and T001 no longer exists

#### Scenario: Ticket for today or the past
- **WHEN** the system date is 2026-10-15 and `TICKET DELETE;T001` is processed for a ticket dated 2026-10-15
- **THEN** the system reports an error and T001 still exists

#### Scenario: Ticket inside a group ticket
- **WHEN** `TICKET DELETE` names an individual ticket generated by a group ticket
- **THEN** the system reports an error and the ticket still exists

### Requirement: Ticket history and persistence
Tickets SHALL be stored in the data directory with identifier, user, date and price, restored at startup, and past tickets SHALL be kept as history. Tickets of a user deleted later SHALL still be restored.

#### Scenario: Tickets survive restart
- **WHEN** T001 exists and the application restarts
- **THEN** T001 exists with the same user, date and price, even if the current price was changed before the restart

### Requirement: Active tickets block user deletion
A user SHALL NOT be deleted while they hold any ticket (bought individually or generated by a group ticket) whose date is on or after the system date. Past tickets alone SHALL NOT block deletion.

#### Scenario: Future ticket blocks deletion
- **WHEN** the system date is 2026-10-01, Ana has T001 for 2026-10-15 and `USER DELETE;ana@correo.com;Clave1!` is processed
- **THEN** the system reports an error and Ana still exists

#### Scenario: Past ticket does not block deletion
- **WHEN** the system date is set to 2026-10-16 and `USER DELETE;ana@correo.com;Clave1!` is processed
- **THEN** Ana is deleted and T001 is kept as history
