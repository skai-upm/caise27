# pass-file-persistence Specification

## Purpose

Defines how SpeedPasses and Special Passes are stored in a text file and restored, linked to their individual tickets, when the application starts again.

## Requirements

### Requirement: Pass file format
Passes SHALL be stored in a UTF-8 text file separate from the other data files, one pass per line, as `Tipo;IdPase;IdTicket;Precio;Consumido` where `Tipo` is `SPEED` or `SPECIAL`, `Precio` has two decimals and `Consumido` is `true` or `false`. The file SHALL be rewritten after every successful purchase or refund.

#### Scenario: File content
- **WHEN** `SPEEDPASS CREATE;SP1;T001;1` succeeds for `T001` priced 40.00
- **THEN** the passes file contains the line `SPEED;SP1-1;T001;8.00;false`

### Requirement: Pass restart recovery
On startup the application SHALL load the passes after the tickets and link each pass to the existing individual ticket (direct or generated by a group ticket) with the stored identifier, keeping its price and consumed status. A line whose ticket does not exist or that is malformed SHALL be skipped with a warning. A missing file SHALL mean no passes.

#### Scenario: Restore passes
- **GIVEN** passes `SP1-1` (SpeedPass) and `VIP1` (Special Pass) were bought for `T001` in a previous run
- **WHEN** the application restarts
- **THEN** both passes exist with the same prices and status, linked to `T001`, and a second Special Pass for `T001` is still rejected
