# F2 - User group management

Objective: Allow existing users to be organized into groups, introducing object relationships and collections.
Description:
The application must allow groups consisting of previously registered users to be created.
Each group must have at least an identifier, a name, and a collection of users.
Commands must be provided for:GROUP CREATE;G01;Familia Garcia
GROUP ADD;G01;ana@correo.com
GROUP REMOVE;G01;ana@correo.com
GROUP DELETE;G01
Users who do not exist in the system cannot be added to a group.
The same user cannot appear twice in a group.
Groups and their relationships with users must persist between application executions using file-based persistence under the restrictions established in Delivery 1.
Main acceptance criteria:
• 
 Groups can be created and deleted. 
• 
 Existing users can be added and removed. 
• 
 Nonexistent users cannot be added. 
• 
 A user cannot appear twice in the same group. 
• 
 The system works with existing users and does not create independent copies of them. 
• 
 Groups are correctly restored when the application restarts. 
• 
 Delivery 1 functionality continues to work. 
• 
 The PlantUML model must be updated to represent the new classes, relationships, and multiplicities.
