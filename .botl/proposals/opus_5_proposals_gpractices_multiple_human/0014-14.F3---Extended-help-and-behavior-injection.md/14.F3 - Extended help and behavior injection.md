## Why

Users need command explanations beyond syntax, and the formatting strategy must be extensible.

## What changes

- Preserve existing `HELP` syntax listing.
- Add `HELP EXTENDED` with each supported command’s syntax and a short purpose explanation.
- Inject the behavior used by the help-generation class to construct its output.

## Scope boundaries

- Do not modify command execution semantics.
- Do not build speculative new UI/help formats now.

## Proposed requirements for delta specs

- **R1:** `HELP` SHALL continue to display recognized command syntax.
- **R2:** `HELP EXTENDED` SHALL display command syntax and brief descriptions.
- **R3:** Help generation SHALL use command information supported by the application.
- **R4:** The help-generation class SHALL receive its output-generation behavior by dependency injection.
- **R5:** Help output generation SHALL remain decoupled from general command parsing/execution.

## Key acceptance scenarios

### S1 — Basic help
- **Given** the application has registered commands
- **When** `HELP` executes
- **Then** available command syntax is shown

### S2 — Extended help
- **Given** the application has registered commands
- **When** `HELP EXTENDED` executes
- **Then** each listed command has syntax and a brief explanation

### S3 — Injected behavior
- **Given** an alternative help-generation behavior is configured
- **When** the help component is initialized
- **Then** it uses the configured behavior without changing the command-processing loop

````text
# F3-C04 — Extended help and behavior injection

"Objective
Extend the help system and prepare its generation for future variants.
Description
The HELP command will retain the concise help based on command syntax. HELP EXTENDED will be added and must also display a brief explanation of each command's behavior.
The class responsible for constructing the help text must receive the behavior used to generate the output through dependency injection. The design must allow new help presentation formats to be added later without coupling them to general command processing.
Acceptance criteria
• 
HELP continues to display command syntax.
• 
HELP EXTENDED displays syntax and descriptions.
• 
Both modes use information about registered commands.
• 
The behavior used to construct help is provided through dependency injection.
• 
The help logic does not directly instantiate all of its dependencies internally.
Mandatory commit
[F3-C04] Add extended help generation"
````
