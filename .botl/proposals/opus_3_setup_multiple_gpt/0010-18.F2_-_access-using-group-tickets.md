### 17.7. F2-C07 — Access using group tickets

The same access operation must support group tickets atomically while respecting the attraction capacity. Consulting attraction status must allow the results of entry and exit operations to be verified.


## Detailed source requirements (verbatim excerpts)

## 10. Access to attractions

Attractions will be accessed using a ticket identifier:

ATTRACTION ENTER;AttractionIdentifier;TicketIdentifier

For example:

```text
ATTRACTION ENTER;A01;T001
ATTRACTION ENTER;A01;TG01
```

The ticket must exist and be valid for the current system date. Its date will be checked only when entering the attraction. Once entry has occurred, the user’s presence in the attraction will not depend on subsequent changes to the system date. If an individual ticket is used, the user associated with it will enter the attraction. If a group ticket is used, all users associated with the individual tickets in its composition will enter together. The attraction must have enough capacity for everyone who needs to enter. Access using a group ticket is indivisible: if capacity is insufficient for all users, none may enter. The operation must take advantage of the common abstraction shared by ticket types and avoid maintaining completely separate access mechanisms.

## 11. Leaving attractions

A user leaves an attraction using:

ATTRACTION EXIT;AttractionIdentifier;Email

For example:

```text
ATTRACTION EXIT;A01;ana@correo.com
```

The operation must remove the specified user from the attraction’s occupant collection and release the corresponding capacity. When several users entered with a group ticket, each may subsequently leave the attraction using their own email address. Users must not store references to attractions they are in.

## 12. Checking attraction status

The application must allow the current status of an attraction to be checked using:

ATTRACTION STATUS;AttractionIdentifier

For example:

```text
ATTRACTION STATUS;A01
```

The operation must display at least:

- attraction identifier;
- name;
- maximum capacity;
- number of users currently inside;
- number of available places;
- users currently inside.

The information must be obtained from the state maintained by the attraction itself. The result must be independent of the way users entered. Once inside, all occupants must be treated as present users, whether they entered with individual or group tickets. Students may decide the exact command output provided that it is understandable and includes all required information.
