Objective
Extend the application to support command execution both interactively from the terminal and from an input file, and add general commands to display available operations and properly terminate the application.
This extension must fully preserve previously developed user-management functionality.
1. Interactive mode
The application must be executable without arguments.
In this mode, it must continuously read commands from standard input.
Example execution:USER CREATE;Ana;Garcia Lopez;12345678Z;ana@correo.com;Clave1!;612345678;1234567890123456
USER UPDATE;ana@correo.com;Clave1!;PHONE;699999999
HELP
EXIT
Each entered line is interpreted as a separate command.
After processing a command, the application must continue waiting for new commands until it receives EXIT or standard input ends.
2. Execution from a file
The application must allow a path to a text file containing commands to be supplied as its first execution argument.
For example:input_basico.txt
The file will contain one command per line:USER CREATE;Ana;Garcia Lopez;12345678Z;ana@correo.com;Clave1!;612345678;1234567890123456
USER CREATE;Pedro;Lopez Martin;87654321X;pedro@correo.com;Otra2#;623456789;9876543210987654
USER UPDATE;ana@correo.com;Clave1!;PHONE;699999999
EXIT
When a file is supplied:
- the application must open it;
- read it line by line;
- interpret each line as a command;
- execute commands in the order in which they appear;
- use exactly the same command processing as interactive mode.
There must not be separate implementations of commands for file and interactive modes.
3. Selecting the execution mode
Application behavior depends on the arguments received by main.
Without arguments
The application operates in interactive mode using standard input.

Subsequent processing must be shared by both modes.
This must allow an equivalent execution to be configured in a development environment:args = [""input_basico.txt""]
4. HELP command
The following command will be added:HELP
This command must display the commands currently available in the application and their basic usage syntax.
For Delivery 1 it must include at least:USER CREATE;Nombre;Apellidos;DNI;Correo;Contraseña;Telefono;Tarjeta
USER DELETE;Correo;Contraseña
USER UPDATE;Correo;Contraseña;Campo;NuevoValor
HELP
EXIT

The information displayed by HELP must be updated as new commands are added in future deliveries.
5. EXIT command
The following command will be added:EXIT
The command must terminate the application in a controlled manner.
In interactive mode:USER CREATE;...
HELP
EXIT
the application will stop asking for new commands after EXIT.
In file mode:USER CREATE;...
EXIT
USER CREATE;...
processing must stop upon encountering EXIT.
Therefore, no command after EXIT may be executed.
6. Invalid files
If the application is given a file argument that:
- does not exist;
- cannot be opened;
- cannot be read;
it must report the problem and terminate in a controlled manner.
The application must not terminate by displaying an unhandled Java exception to the user.
7. Blank lines
Blank lines in an input file must be ignored.
For example:USER CREATE;Ana;Garcia Lopez;12345678Z;ana@correo.com;Clave1!;612345678;1234567890123456

HELP
EXIT

must be processed correctly.
8. Shared processing
Interactive mode and file mode are merely two different ways to provide commands to the application.
Command interpretation and execution must be shared.
The logic for the following must not be duplicated:
- USER CREATE;
- USER DELETE;
- USER UPDATE;
- HELP;
- EXIT.
The same command must yield the same result whether supplied via terminal or file.
Technical constraints
The extension must:
- retain Java 21;
- retain Maven;
- use only the Java standard library;
- retain compatibility with all existing Delivery 1 functionality;
- use standard input when no file is supplied;
- use the first argument of main as the file path when supplied;
- process the file line by line;
- reuse the same command-processing mechanism in both modes;
- handle errors opening and reading the file in a controlled manner.
The following must not be done:
- use external libraries to process commands;
- introduce frameworks;
- introduce design patterns intended for later deliveries yet;
- unnecessarily modify the user model;
- anticipate features of future deliveries.
The project must continue to compile and successfully pass all its tests using:
mvn test
Acceptance criteria
- The application runs from a terminal without arguments.
- The application accepts commands interactively.
- The application can receive a file path as its first argument.
- Each nonempty file line is processed as a command.
- Commands are processed in their given order.
- Terminal and file use the same processing mechanism.
- HELP displays available commands and basic syntax.
- EXIT properly terminates interactive mode.
- EXIT immediately stops file processing.
- Commands after EXIT are not executed.
- A nonexistent or unreadable file is handled in a controlled manner.
- Blank lines do not cause errors.
- All previous user-management functionality continues to work.
- mvn test continues to pass the existing tests.
