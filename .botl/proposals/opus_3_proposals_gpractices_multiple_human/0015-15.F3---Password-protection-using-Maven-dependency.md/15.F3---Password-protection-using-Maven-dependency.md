## Why

Passwords must no longer be persisted as plaintext, while existing user authentication operations remain functional.

## What changes

- Add BCrypt as a Maven dependency.
- Hash newly created or updated passwords prior to persistence.
- Verify credentials against stored hashes in commands such as `USER DELETE` and `USER UPDATE`.

## Scope boundaries

- Preserve E1 password validation before storing the hash.
- Do not introduce other authentication schemes or invent automatic migration for older files.

## Proposed requirements for delta specs

- **R1:** The Maven build SHALL declare a compatible BCrypt dependency.
- **R2:** Persisted new passwords SHALL be BCrypt hashes rather than plaintext passwords.
- **R3:** `USER DELETE` and `USER UPDATE` SHALL verify submitted passwords against stored hashes.
- **R4:** Password changes SHALL generate and persist a new BCrypt hash.
- **R5:** Password validation requirements from E1 SHALL still apply to new passwords before hashing.

## Key acceptance scenarios

### S1 — Persisted secret
- **Given** a valid user is created
- **When** the user file is inspected
- **Then** the original plaintext password is not stored

### S2 — Authenticated delete
- **Given** an existing user enters the correct or incorrect password
- **When** `USER DELETE` executes
- **Then** deletion succeeds only for the correct password

### S3 — Authenticated update
- **Given** an existing user attempts an update with an incorrect current password
- **When** `USER UPDATE` executes
- **Then** the update is rejected without changing stored data

### S4 — Password rotation
- **Given** a user changes to a valid new password
- **When** the application restarts
- **Then** the new password authenticates against a newly stored hash

## Design and implementation planning notes

- Use the chosen library’s normal salt and verify functions.
- Document behavior for pre-existing plaintext files instead of silently promising migration.

- Verify `mvn test` and `mvn package` as applicable; run OpenSpec validation before applying and verify the implementation before archiving.
- Preserve pre-existing E1/E2 behavior and the exact user-facing command syntax.

"Objective
Prevent storage of plaintext passwords and add an external library through Maven.
Description
A simple Maven dependency will be added to protect passwords using BCrypt. Passwords must be stored as hashes, and operations requiring authentication must verify the supplied password against the stored value.
The password format validation defined in E1 still applies before generating the hash.
Acceptance criteria
• 
The BCrypt dependency is declared in pom.xml.
• 
New passwords are not stored in plaintext.
• 
USER DELETE correctly validates the password.
• 
USER UPDATE validates the current password.
• 
Changing a password persists a new hash.
• 
The password format rules from E1 continue to apply.
