# F2 - Individual ticket management

Objective: Introduce individual-ticket purchases for a specified date and associate them with system users.
Description:
The application must allow a registered user to buy an individual ticket for a particular date.
Each ticket must contain at least:
• 
identifier;
• 
date of use;
• 
associated user;
• 
price.
An example command is:TICKET CREATE;T001;ana@correo.com;2026-10-15
Tickets must be stored persistently and restored when the application is started again.
Past tickets must be retained as historical records.
The price will be an internal variable initialized to 40.00 on each execution, so it does not need to be persisted.

On success, the command will return:OK TICKET CREATED -> <Precio>

The existence of tickets also changes the Delivery 1 rules for deleting users. A user with any ticket dated on or after the current date configured through SYSTEM DATE cannot be deleted.
For example:SYSTEM DATE;2026-10-01
TICKET CREATE;T001;ana@correo.com;2026-10-15
USER DELETE;ana@correo.com;Clave1!
Deletion must be rejected.
We also add:TICKET DELETE;T001
Deletion is allowed only if the ticket date is in the future (later than the system date; today does not count).
If subsequently:ticketDate >= SYSTEM DATE blocks deletion.SYSTEM DATE;2026-10-16
ticket T001 no longer, by itself, prevents the user from being deleted.
To change the ticket price we add the command: SYSTEM PRICE;60.00

Main acceptance criteria:
• 
 Tickets can only be created for existing users. 
• 
 Every ticket has an identifier, date, user, and price. 
• 
 Tickets persist between executions. 
• 
 Past tickets are retained as historical records. 
• 
 A current or future ticket prevents deletion of its associated user. 
• 
 A past ticket does not, by itself, prevent deletion of the user. 
• 
 All checks use the configured system date. 
• 
 PlantUML must reflect the new classes and relationships. 
• 
Tickets hold a reference to the user to whom they belong.
