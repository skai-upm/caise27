## Authoritative detailed requirements (verbatim source excerpts)

## 6. Attractions

The park will contain different attractions. Each attraction must have at least:

- a unique identifier;
- a name;
- a maximum capacity;
- a collection of users currently inside it.

An attraction may be created using:

ATTRACTION CREATE;Identifier;Name;Capacity

For example:

```text
ATTRACTION CREATE;A01;Dragon Rojo;20
ATTRACTION CREATE;A02;Torre del Cielo;12
```

Capacity represents the maximum number of people who may be in an attraction simultaneously. The relationship between an attraction and its occupants will be unidirectional. The attraction must hold references to the users currently inside it, but users must not store any reference to the attraction they are in. The application must provide an easy way to consult the users currently in an attraction using:

ATTRACTION LIST;AttractionIdentifier

For example:

```text
ATTRACTION LIST;A01
```

The operation will display the email addresses of the users inside the attraction at that moment. If there are no users, it must produce an empty or equivalent result in a controlled way. This is a read-only operation and must not change the state of the attraction.
