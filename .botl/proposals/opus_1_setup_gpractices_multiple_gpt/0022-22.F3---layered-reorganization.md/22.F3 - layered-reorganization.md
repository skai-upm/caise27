## Authoritative detailed requirements (verbatim source excerpts)

## 3. Layered application organization

The code must be reorganized so that presentation, business, and persistence responsibilities are clearly distinguishable. At a minimum, the project must have separate Java packages for:

- presentation, responsible for user interaction and command processing;
- business, responsible for the model, business rules, and application control elements;
- persistence, responsible for repositories and reading and writing persistent information.

These packages may be placed within the chosen root package and further divided into subpackages when necessary. The default package is not allowed. The reorganization must preserve the separation of responsibilities introduced in previous deliveries. In particular, the presentation layer must not access persistence files directly, and domain objects must not be responsible for directly storing or retrieving their persistent representations.

## 4. Handling exceptional situations

From this delivery onward, exceptions must be used to represent and propagate abnormal situations that may arise during system operations. Students may decide whether to use a centralized exception hierarchy or specific exceptions distributed across the different domain and application elements. In either case, exceptional situations must be handled in a controlled manner at the appropriate application level. An incorrect command or an operation that cannot be completed must not cause command processing to terminate unexpectedly. Exceptions must be used as part of the application design, not merely as a mechanical replacement for messages printed on screen.
